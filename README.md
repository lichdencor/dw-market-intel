# market-analytics-dw

Star schema data warehouse for US tech sector market analysis.  
Integrates daily **OHLCV prices** (Yahoo Finance) and **insider trading** (SEC EDGAR Form 4) into a dimensional model backed by PostgreSQL, with a DuckDB OLAP computation layer and Metabase dashboards.

> University project — UB Database Systems 2 · 2026

---

## What it does

- Tracks **30 US tech tickers** (AAPL, MSFT, NVDA, GOOGL, META…) with daily price history
- Collects **SEC Form 4** filings — the mandatory insider transaction reports filed within 2 business days
- Computes **technical indicators** (SMA 20/50/200, Bollinger Bands, volume ratio) via SQL window functions
- Calculates **insider net signal** (-1 = pure sell → +1 = pure buy) per ticker/period
- Answers: *what happens to a stock's price 5, 10, and 30 days after an insider open-market purchase?*

## Architecture

```
Yahoo Finance + SEC EDGAR
       │
       ▼  Collector (Python, batch mode with rate-limit backoff)
    MinIO  ←─ raw-ohlcv/{date}/*.csv
       │
       ▼  ETL (Package pattern — extract → profile → stage → load)
 PostgreSQL 17  ──── DW schemas ─────────────────────────────────
   staging.*  (raw TEXT, UNLOGGED)
   dw.*       (star schema — 2 facts, 5 dims, SCD Type 2, RLS, audit)
   profiling.*(ETL run history + column stats)
       │
       ▼  DuckDB worker (ROLLUP, CUBE, ASOF JOIN — columnar/vectorized)
 PostgreSQL 17  ──── OLAP results ───────────────────────────────
   cube.*     (ticker_summary, price_by_sector_period,
               insider_pressure, post_insider_return,
               price_daily_enriched)
       │
       ▼  Metabase v0.59
   Analyst    → cube.* only  (bi_user — OLAP results, no raw DW access)
   Operator   → dw.* + profiling.* (dw_user — ETL health, quarantine)
```

## Quick start

### Prerequisites
- Docker Compose on `10.10.10.20`
- PostgreSQL 17 running on `10.10.10.10` with `dw_analytics` database

### 1. Configure credentials
```bash
cp .env.example .env
# fill in your values
```

### 2. Apply the database schema
```bash
psql -h 10.10.10.10 -U postgres -d dw_analytics -f schema-simple/ddl_schema.sql
```

### 3. Start services
```bash
make up          # MinIO + Metabase
```

### 4. Run the data pipeline
```bash
make streamline  # collector → ETL → DuckDB OLAP refresh
# takes ~15–30 min depending on SEC EDGAR rate limits
```

### 5. Verify
```bash
make counts      # row counts per table
make check       # referential integrity check
```

### 6. Expose publicly (optional)
```bash
make expose      # Cloudflare Quick Tunnel — prints 3 HTTPS URLs
make unexpose    # shut down tunnels
```

## Data model

### Facts

| Table | Grain | Key metrics |
|---|---|---|
| `fact_price_daily` | ticker × trading day × period | OHLCV, SMA 20/50/200, Bollinger Bands, volume ratio, is_suspect flag |
| `fact_insider_daily` | ticker × day × insider × transaction type | shares, price, total value, shares owned after |
| `fact_price_monthly_snapshot` | ticker × month | open/close/high/low, monthly return, avg volatility |

### Dimensions
`dim_ticker` (with SCD Type 2 history) · `dim_date` · `dim_period` · `dim_insider` · `dim_transaction_type`

### OLAP layer (computed by DuckDB, stored in `cube` schema)

| View | Aggregation | Use case |
|---|---|---|
| `ticker_summary` | Per ticker snapshot | YTD return, annualized vol, insider signal, days since last insider |
| `price_by_sector_period` | ROLLUP(sector, year, quarter, month) | Sector performance drilldown |
| `insider_pressure` | CUBE(symbol, direction, year, month) | Net insider signal across all dimension combinations |
| `post_insider_return` | ASOF JOIN on dates | Return 5/10/30 days after open-market insider buys |

## ETL observability

Every pipeline run writes to `profiling.run_log` and `profiling.column_stats` — queryable from Metabase via the Operator connection. HTML reports generated by ydata-profiling are served at `http://10.10.10.20:8080`.

---

## Access control

The analyst (`bi_user`) connects to PostgreSQL but can **only see `cube.*`** — pre-computed OLAP results. Direct queries against `dw.fact_price_daily` return `ERROR: permission denied for schema dw`. The enforcement is structural (PostgreSQL roles), not just a BI configuration.

```
bi_user  → cube.*          (OLAP results — analyst)
dw_user  → dw.* profiling.*  (raw DW — operator)
etl_user → all schemas (write)  (pipeline only)
```
